Reading this chart: the X-axis is wall-clock time - when each event was actually recorded. The Y-axis is a watermark value, which happens to be a timestamp too, but a different one - it's not "now," it's event-time progress. A marker that doesn't sit exactly on the blue line isn't a bug: it usually came from a different operator (or a different parallel subtask) than whatever's currently drawn as the line, reporting its own watermark as observed at its own point in the pipeline.
Watermark advance - Flink's estimate of "no more event-time data older than this is coming." Everything else is measured relative to it.
Window fired (on time) - your window function ran because the watermark passed the window's end.
Window fired (late update) - a late element arrived within allowedLateness, so the window re-ran with the updated element set.
Late drop - an element arrived too late even for allowedLateness and was discarded without ever reaching your window function.
Event bucket count - how many elements passed through the tap in each ~1s sampling window, regardless of whether they were late.
Drag on the chart to zoom into a time range.
